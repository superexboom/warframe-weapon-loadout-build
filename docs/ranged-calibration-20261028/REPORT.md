# 远程武器原生机制覆盖盘点，2026-10-28

本轮按游戏资源、Luau、当前保留EXE的实际消费者检查，不以WFSim配装或相同分数作为正确性标准。目标是建立独立的可重复校准依据，并修复已闭环的机制；不能把“未报warning”当作完整校准。

## 有多少尚未校准

当前运行目录有399条远程武器记录：208主武器、171副武器、20空战武器，合计607个显式模式。600个有正伤害数据可进入评估，6个是辅助近战动作，Coda Bassocyst副射击没有独立伤害数据；另有6条通用／组装记录本身无模式。变体独立计数，不等同于399个不同机制。

基线的三组4秒探测（常态、假设满触发、多重／状态／全头部）明确报缺口的是13把、14模式。这只是已有诊断的下限：586个模式没有报缺口，不能因此认定它们已完成原生校准。本轮补充诊断后为17把／18模式显式报缺口；这是暴露原有遗漏和边界，不是修坏了四把武器。

- 517模式的GunCO分类仍带社区参考来源。此数是模式数，不是517把武器，也不表示517模式都错。
- 87模式的特殊机制只带社区参考来源记录，未记录独立原生证据。
- 94模式的特殊机制带有原生来源声明；原生字段出现也不等于已追完最终触发、叠加和目标处理。计数按当前选择模式隔离；修正了初版统计把兄弟模式来源递归算入主模式的问题（初报116／86，复核94／87）。本轮之后有97模式带原生来源声明。
- 同伴另外24条记录／24模式；加入后为423记录、631模式、624可评估，基线16把／17模式有明确缺口。没有把同伴混入上述远程分母。

本轮形成**62把具名武器／变体的优先核查清单，71个条目**，见[triage-ledger.json](triage-ledger.json)。它包含已知模型限制、明确遗漏、需要追消费者的候选、仅可能影响多目标的空间机制。**62不是错误武器总数，不是全部未校准武器数，也不是完成率。** 全部未校准总数尚不能可靠给出：通用MOD／赋能的调用资格还横跨几百个模式。

## 原生盘点覆盖

扫描完整保留Packages目录468745条／468744唯一实体，并提取相关武器祖先、投射物、脚本引用和伤害触发器。607导出模式引用262种不同投射物，声明引用展开覆盖498种投射物、6伤害触发器、13行为和863支持对象，共1899份原始属性哈希。展开包含备用、继承、表现和PvP引用，不能当作1380个实际伤害事件。

12模式声明光束链，10模式声明射线弹跳；它们都没有对应的基线缺口提示。链路对其他目标的加成在当前单体场景可以有意省略，但“会不会返回原目标”“是否另计暴击／状态／击杀归属”仍需验证。另有30个命中径向开关、28个未命中径向开关；先滤零伤害占位再追实际分支，不能把数量直接算成bug数。

607导出模式与607原生普通行为是数字巧合：按原始索引只匹配606；Acrid辅助模式和Imperator新行为存在来源映射债务。空战还存在28个HeavyBehaviors，部署状态必须独立检查。

另作导出→运行时核对：121模式有正secondary组件声明，102模式有某种副伤害运行时对象，5模式的主payload本身已经是该范围包，因此排除重复计数；剩余14模式／14武器path完全未见副伤害对象且基线无warning。其中Phantasma／Prime的73爆炸已由实际consumer确认，其他需继续排除休眠继承、替代分支或纯控制效果。

14个候选：Tenet Plinx、Miter、Nox玩家别名“Grakata”、Buzlok、EFV-8 Mars、Arbucep、Larkspur／Prime、Grimoire、Phantasma／Prime、Scourge Prime、Acceltra、Aeolak。“Grakata”按真实path保存，不与普通Grakata合并。

## 本轮确定的机制和修正

### Battacor／武使之力

副射击有独立208 Radiation范围包，20%暴击／2倍、50%状态，与208直击的34%／3倍、8%状态不同。原始consumer的false分支跳过单个范围包的额外多重倍率，但逐射线是否另发多个范围包尚未闭环。当前模型保留每trigger一个范围包策略，新增次数未验证诊断。一次射击、关闭暴击状态时，MS1是208直击+208范围=416；MS3是624直击+208范围=832。这是当前模型策略下的无减伤算例，不是native总伤公式或实机DPS。范围GunCO沿用通用默认不计策略，并明确标注资格未验证；本轮没有独立证明Battacor范围不吃GunCO。

新增原生来源绑定导入器与回归。0蓄能不能使用副射击，1／2／3蓄能可使用，消耗0配置表示消耗全部当前蓄能；不能强制套满3杀。当前采用“第一发主武器击杀取得1蓄能后立即使用副射击”的明确策略，消费前snapshot→清空→state multiplier已用原字节验证，1／2／3蓄能各取1／2／3倍且不随消费后live gauge变化。当前只实现立即使用1蓄能策略，2／3蓄能积攒策略和Sentient Barrage增幅另留待实现。现有通用蓄力节奏还把等待放在射击后，首发windup及动态增益snapshot时点明确标为未建模／未验证，不宣称整个副射击循环已精准。增幅会关闭基础范围包并启用命中脚本，不能只加暴击而保留原爆炸。

### Zymos／邪莫斯

原生脚本确实包含OnRadialDamage和OnDeath子弹体创建分支，每条候选分支把carrier的请求数量设5。两条分支共享嵌入metadata，不能相加成10，也不能直接给每发加5×333。

子弹体声明333 Toxin、30%状态、5%／2.3倍暴击，SendEvents=0、DamageUpgradeTypes空表；carrier同时复制子弹体damage info。这证明部分投射物通知被跳过，但不证明继承的父伤害未经MOD，也不证明全部异常／击杀赋能失效。现有61立即爆炸、953头部延迟爆炸保持；新增明确未闭环诊断和来源，修正旧注释“缓存没有Lua、目标死了无需算孢子”的错误说法。

### Phantasma／幻离子及Prime

主爆炸选择的73 Radiation包保留DHT_PROJECTILE=2，同时设置独立的head-damage suppression；默认范围类型4只补未指定的0，不覆盖显式2。因此“空间爆炸”“包类型”“普通头部增伤”“弱点／击杀通知”是不同轴。实际运行时核对确认：当前只算15接触伤害，73主爆炸未进入replay，之前也没有warning。已增加主爆炸／子弹体遗漏和CO／头部事件未闭环诊断；不把猜测的完整事件加入评分。原生元数据导出补回sourceHitType。完整GunCO数值及只应用一次仍须追实际武器上下文，不能仅改成area_direct便自动开放全部头部和CO效果。

进一步确认普通武器、无parent句柄时，目标侧CO hook的资格函数拒绝；以PowerSuit／Ability为parent的正对照可进入。此控制结果不证明正常装备流程的parent始终为空，区域受害者和接触包也不同，因此最终武器系数暂不修改。

### 通用GunCO核心

在原EXE字节上独立执行36个控制算例。核心检查实际proc上下文、DoT和来源，不直接排除radial。控制例：caller base100、当前伤害200、两种异常、每种0.8，具备相应升级上下文时结果360；无升级上下文时仍200；caller base改为200则520。上下文和传入基数决定最终乘区，不能用“投射物一定独乘／范围一定不吃”替换数百条分类。

可复现工具：`tools/verify_native_co_contract.py`。外部状态列表、升级查询和当前伤害读取明确stub；执行的是原核心，不是假装完整游戏世界。这36例不校准任何具体武器最终DPS。

### 延迟爆炸通知：原提案已撤回准入

Kompressa、Zakti、Lenz、Sporothrix及变体的延迟范围伤害有结算但无第二次普通命中／暴击通知。条件过滤器本身允许radial，不足以证明应再通知。继续追查发现SendEvents有“每投射物一次”的锁；真实damage-controller到challenge-manager还有独立路径。原本地提案16例仅说明加事件会改变计数，不能作为游戏正确性。本轮不据此增加命中次数或Enervate层数，避免制造双算。
