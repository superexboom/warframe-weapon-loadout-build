# 史特克模型修补与守望 Prime 的 KPM 差异

> 后续修正：本报告的“所有史特克胶团都是径向伤害”已被主胶团范围直击证据推翻；守望变形时长也补上装填速度。请以 [本轮更新](PROJECTILE-CLASSIFICATION-2026-10-26.md) 为准。下文保留此前测量，不能当作最终模型结果。

本轮按用户要求采用史特克正常满层引爆，不模拟官方的初生满层回调缺失；单体场景默认子胶团位于目标脚下，按完整爆炸伤害结算。守望使用用户提供的 `wf-riven-build-A (2).json`，SHA-256 为 `07e264770687f08f4a5a2a81a8ab1106a69f62d3ac7906abba87d3284d246870`，原文件未修改。

## 结论

守望的差距同时来自场景设置和本地模型遗漏。原文件复现为 43.1975 KPM；它是 **30 秒、未瞄准、额外 Archimedea 超宏、Roar 强度 8.75** 的场景。公开榜单约 166.6667 的行是 **180 秒、瞄准、普通钢铁之路 Thrax、没有外部技能增益**。不能把这两个数直接当作同条件引擎差异。

同时，本地代码确实错误地排除了灵化守望的狙击连击和瞄准倍率，遗漏了爆头生成球的独立存续及特殊倍率继承。这些问题已修复。

| 对照场景 | Portable 修复后 KPM | WFSim 当前引擎 KPM | 相对差异 |
|---|---:|---:|---:|
| 原文件，30 秒，未瞄准，复制完全相同的目标防御池 | 43.6390 | 42.2336 ± 0.1612 | +3.33% |
| 同上，仅改为瞄准 | 177.0559 | 178.0301 ± 0.0566 | -0.55% |
| 180 秒榜单环境，精确使用用户紫卡数值与功能卡等级 | 163.1667 | 166.6399 ± 0.0616 | -2.08% |
| 同一榜单环境改为 30 秒 | 121.4667 | 109.3607 ± 0.2446 | +11.07% |
| 180 秒榜单环境，加原文件 Roar、保持瞄准 | 182.2917 | 183.3502 ± 0.0154 | -0.58% |

WFSim 每行 1,000 次，± 为均值标准误，不是误差上限。短窗口仍有明显偏差，不能宣称两套模型完全等价。Portable 的确定性期望、弱点击杀分支和整次射击处理，与 WFSim 逐弹头随机回放在启动、状态及击杀时点上仍有差异；它们对剩余误差的各自贡献没有全部拆完。修复后的数值没有通过经验倍率向榜单拟合。

## 史特克

- 多重在新胶团上形成初始叠层，再以整团进行碰撞合并。跨枪的 3+3 被限制为 5，不再把合并溢出的第六层自动当成新的胶团。
- 采用正常满层引爆：普通形态上限 10，灵化形态上限 5；满层的初生胶团在命中点引爆，忽略当前游戏的回调缺失 Bug。
- 子胶团数改为脚本中的向下取整。常规可用数量充足时，1/2/3/4/5 层生成 2/2/3/4/5 颗。
- 加入同一回放内的 70 颗子胶团存量上限，寿命结束释放数量。
- 默认所有生成子胶团命中目标，计算 2 次弹跳爆炸及末次 2.5 倍爆炸；原有显式命中数、弹跳次数和时序参数仍可覆盖，显式 0 可用于分量分析。
- 子胶团独立于母胶团所击杀的目标存续，在固定目标位置继续结算。
- 所有胶团爆炸保持径向伤害身份，不获得普通弱点、敏锐或紫卡弱点加成，不产生死首的弱点击杀触发。

默认的两次弹跳接触忽略飞行间隔，末次按已有 4 秒寿命参数结算。这是用户指定的单体、全部命中假设，不是三维弹道的实测还原；小数多重继续使用期望部署量，未增加随机弹道模拟。前端已写明这些默认值。

实际自动配装验收：灵化史特克、9999 级钢铁之路 Thrax、30 秒、fast、自动赋能，约 139.7 秒，17,337 次原生评估、0 次 Python 回退。选中 Secondary Fortifier（次要坚毅），没有选择死首。求解目标与手动回放均为 **19.2118697978 KPM**。

## 守望修复内容与依据

**灵化形态保留狙击机制。** 当前游戏 `PrimeVectisRifle` 的两个攻击块都声明 `SniperImpactBehavior`，灵化攻击仍有 `BaseHitCount=5`、`BaseHitMultipler=0.5`、每阶三倍命中数、2 秒衰减参数；基础守望也保留对应攻击行为。之前代码硬编码所有灵化形态不建立、不使用狙击连击，现改为数据声明的灵化模式继承。瞄准加成和连击建立按实际瞄准选项启用，未瞄准不再暗中当成开镜。

**爆头球的独立生命周期。** 当前 `VectisIncarnon.lua` 的停止回调会结束旧投射物并生成独立的增长球。回调中伤害控制器的检查对应 `mInvulnerable`，不是死亡检查。旧回放在直击击杀后跳过所有径向分量，并把已排队爆炸绑定到旧目标 generation；这使本应在 0.4 秒后发生的独立爆炸消失。现在仅标记过的独立爆炸继续保留，并作用于同一位置立即补入的下一只目标。这符合当前单体连续击杀的场景定义，其他普通爆炸未无条件获得该行为。

**特殊的爆头倍率继承。** 守望的爆头球爆炸继承武器自身的瞄准／死首倍率，但不获得敌人头部本身的 x3、不获得爆头暴击额外倍率，也不获得敏锐／紫卡的弱点伤害或弱点暴击。它仍然是径向伤害，不能自己触发弱点击杀赋能。该特殊继承由 WFSim 作者的游戏实测 [M117](https://github.com/magenie33/wfsim/blob/13640639/docs/measurements/M117-chamber-and-sniper-combo.md) 和 [M118](https://github.com/magenie33/wfsim/blob/13640639/docs/measurements/M118-vectis-prime-compression-and-combo-order.md) 支持；不是将规则推广到史特克、沙皇等爆炸武器。回归使用其 1484 与 1762.25 的非暴击伤害例子，额外加入弱点词条验证不会错误继承。

**时间与状态伤害。** 球的后续身体伤害修正为 1、2 秒；狙击连击倍率也传给该次攻击产生的状态伤害种子，触发次数不变。M117 给出了这项状态伤害继承的直接测量。

从统一榜单环境的旧模型到本轮修复，各步探索记录为：约 40.47 → 86.54（灵化狙击机制）→ 113.46（爆炸倍率与已生成球存续）→ 163.17（直击击杀仍生成独立爆头球）。这些是诊断时的顺序消融，不代表可独立相加的增益。

## 验证与交付边界

Python 与 Rust 同步实现，并加能力标记；旧 native 库缺少这些行为时会回退到正确的 Python 实现。保留原有用户修改，未触碰 Bot，未烘焙缓存，未构建 Portable EXE。仅编译本地 Rust 核心用于验证。

重点回归包含史特克初生满层、3+3 合并、小数多重、子胶团数量、存量上限释放、母胶团击杀后子胶团存续、死首触发隔离、守望击杀球、倍率实测点、狙击状态伤害，以及原生影子一致性。

测试覆盖 1,342 个唯一用例。全量运行 1,341 个用例时，1,340 通过、12 个 subtests 通过；唯一失败发生在测试进程先加载旧 native DLL、随后子胶团存续实现更新造成的新旧混用。最终库的新进程重跑全部相关 117 项通过，并另跑 17 项进化事件回归通过；包含该失败项及后来增加的用例，覆盖合并后没有未解决失败。没有把这次验证描述成一次完全干净的最终全量运行。Rust 测试构建成功（crate 本身没有 Rust 单元测试，原生行为由上述 Python shadow 用例验证），前端 JavaScript 语法检查通过。
