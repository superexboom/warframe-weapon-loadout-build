# Portable：CPU 深度搜索与离线烘焙

2026-11-18，基线为 `main` 的 `7a74447`。这次优化的是默认 CPU/Rust 路径，既用于 Portable 烘焙也用于提交紫卡后的实际解算；GPU 保持关闭，Bot 单独评估。没有更改评分公式、候选池、beam 宽度、爬山轮数、推荐数量或交互时限。

## 节省的工作

- **状态池。** 每次应用会产生至多三项概率转移，改用定长存储。加入、过期和换目标时复用概率分布缓冲；前缀和转移仍按原顺序累加，腐蚀的护甲计算直接读取同一份分布。
- **候选面板。** 每种武器形态只读取一次忽略爆头伤害加成的规则，原生层按原字段顺序返回。普通 MOD 不再为每张卡临时创建效果列表；套装加成和跳过原因的顺序不变。新旧 Python 适配器混用新核心时也保留太始弓及灭杀者副射击的爆头规则。
- **目标硬度。** 同一配装比较多个血量点时，只序列化一次配装。分片内的回放缓存按完整目标上下文的摘要区分目标；每一个硬度点仍独立解算，权重、低高血量点和回退到逐场计算的语义均保留。
- **只取分数的战斗回放。** 搜索不用把完整的诊断报告从 Rust 传到 Python。没有弱点击杀触发、补弹或概率分支时，无需保存每击归因记录。普通击杀、护盾穿透、爆头伤害、弹匣状态及所有会改变后续输出的触发仍照常计算。手动模拟和生命曲线仍取完整数据。

## 对照条件

Windows、同一台机器、release 原生库。两把武器为卡拉克（主武器，首模式）和急冻喷枪（同伴武器，首模式）；两个进程，各自串行，`--status-tables off`。每把每档均完成三正、两正的推荐及负面评估。`deep` 旧版从独立源码和原生库运行；`fast` 旧版沿用同机、同提交、同线程数和完全相同输入的原 CPU 对照。每个版本、档位使用独立空分片目录，均不发布主缓存。

分片验证排除引擎变动必然改变的顶层 `inputs`，其余内容连同键顺序逐字节比较。另比较两份正面结构各自的评估次数、搜索缓存命中、各项负面搜索和预算截断计数。单独计时的紫卡请求使用对应版本的 `deep` 分片，清空完整请求结果缓存；卡拉克倾向 1.2，暴击率 +173.3331%、暴击伤害 +147.4523%。新旧版本均在独立进程中使用一个解算线程；请求耗时不含进程启动和游戏数据加载。

## 实测结果

| 工作量 | 基线 | 优化后 | 耗时减少 |
| --- | ---: | ---: | ---: |
| `deep` 完整冷分片，两把武器并行，各一轮 | 185.835 秒 | 158.032 秒 | 15.0% |
| `fast` 完整冷分片，条件同上 | 121.647 秒 | 104.774 秒 | 13.9% |
| 卡拉克 `deep` 实际紫卡请求，无完整请求缓存，三轮中位数 | 7.533 秒 | 6.679 秒 | 11.3% |

`deep` 中卡拉克的分片从 180.60 秒降到 152.87 秒，急冻喷枪从 147.77 秒降到 135.46 秒。两者合计的进程 CPU 时间由 325.83 秒降至 287.06 秒。两个分片并行，表中的总耗时不能按单武器时间相加。

两档共四个分片的条目完全一致。`deep` 的三正/两正评估次数分别为卡拉克 50,605 / 22,046、急冻喷枪 35,381 / 1,118；各阶段计数与基线一致，均未触发截断。指纹从 `5ed976bf545120d9` 变为 `551f81d8284f121c`。`deep` 两份 `entries` 按原键序、UTF-8 紧凑 JSON 计算的 SHA-256：

- 卡拉克：`52c1cd56ecf992eeadd7b4739bfcefef5b80d49a530874183667a1cae52807da`。
- 急冻喷枪：`5885a7f7a82fb6cf486eb2088b66b5e71412e9b83f82177d8cc9d77817165b2a`。

实际请求在上述烘焙全部结束后，以旧/新、新/旧、旧/新的顺序各跑三次。旧版 7.349、7.533、7.629 秒；新版 6.674、6.967、6.679 秒。每次进行了 6,884 次候选评估，基准配装、实际紫卡配装、路线、赋能、负面评估和目标校准逐项相同，实际配装评分都是 `33.239213898933116`。两种武器的烘焙样本不足以外推四小时全目录 `deep` 的时长。

## 复现

在要比较的每个源码版本分别构建原生库并指定新的 `$out`，不要复用一个版本已生成的分片。命令只会生成两把武器的分片。

```powershell
python tools/build_native.py
$out = '.local/cpu-deep-compare/current'
$env:WF_ANALYSIS_STATICS_CACHE_PATH = "$out/isolated.json"
python tools/bake-analysis-statics.py --profile deep --workers 2 --status-tables off --shards-only --shard-dir $out --report "$out/report.json" --weapon /Lotus/Weapons/Grineer/LongGuns/GrineerM16Homage/GrineerM16Rifle --weapon /Lotus/Types/Friendly/Pets/MoaPets/MoaPetComponents/CryoxionWeapon
```

局部状态池对照使用取自 15 把武器的 60 个池、28,811 次操作；逐步对比分布、均值、状态版本和存活状态，结果一致。交替运行九轮，旧/新状态池中位数约 555/256 微秒。该计时仅用于解释热点，不代表完整烘焙能快一倍。下一轮应在长寿命毒气和有持续投射物的灵化武器上单独取样，再评估全目录的总时间。
