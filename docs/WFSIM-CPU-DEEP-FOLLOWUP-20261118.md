## 未硬套的规则

- [主要·衰弱](https://github.com/magenie33/wfsim/blob/7f286c22ba/docs/PRIMARY_DEBILITATE.md)：目标已有十层且本次包确实含该复合异常，才有一次拆分机会；同包重复选中的基础异常合并，子包按身体落点。能确认回调内部，不能从平均异常次数恢复每次攻击实际进入几次回调、哪些种类同包出现。手动页允许装备并说明未计分，自动计算不将它当成通用状态率。
- [次要·照射](https://github.com/magenie33/wfsim/blob/7f286c22ba/docs/SECONDARY_IRRADIATE.md)：回声溅射其他目标。单体继续不算自溅射。链、反弹和穿透命中在群体场景能否回打原目标，须区分真正的通知生产者及其先后；不把某个实测武器的读数设为全武器常量。仲裁靶场尚未实现该回声通知。
- 上游 capped stack 的 FIFO 调整和统计／队列更新不需要逐项移植。Portable 使用独立的期望状态池；没有将上游离散采样器替换进每个候选，也没有修改近战动画或 Bot 搜索预算。

## CPU 对照

Windows、release Rust，外层两个武器进程，各自一个解算线程，GPU 关闭。毒芽 Prime（Zakti Prime，主模式）用延迟毒气爆炸；棱晶·安格斯壮（Prisma Angstrum，模式 1）用灵化弹头。各版本从无分片的独立目录启动 `deep`，均完成三正、两正及负面复核，均未截断。基线源码、数据及 `.pyd` 独立冻结。测试只写分片，不替换主缓存。

| 旧规则，同一工作量 | 毒芽 Prime | 棱晶·安格斯壮 | 并行墙钟 |
| --- | ---: | ---: | ---: |
| `64be5f6` | 71.881 s | 78.085 s | 83.418 s |
| 只优化 Rust 状态池 | 70.246 s | 76.827 s | 82.059 s |
| 加上单个候选内的形态／攻击配置复用 | 67.238 s | 74.856 s | 80.507 s |

三组的两份 `entries` 及每阶段搜索次数完全一致；两把武器各为 36,190 + 1,176、57,146 + 1,186 次评估。固定工作量的并行耗时减少 **3.5%**，两进程 CPU 时间合计从 148.39 秒降至 141.20 秒。按原键序压缩为 UTF-8 JSON 的 `entries` 哈希前缀分别为 `825bae48e1ba9aab75`、`19ec924b2131a23472`（按分片文件名排序）。只测了两把，不能从这次测量推算全目录四小时会缩短多少。

另用不击杀的高血量目标，固定原版毒芽 Prime 无卡手动回放 30 秒，并确认每次有 12,805.80 毒气跳伤。固定单一逻辑 CPU，旧／新／新／旧交替，每版本每种爆头率 6 批，每批 75 次；两版每批配装与伤害一致，均无原生回退。0%、50%、100% 的中位耗时分别为 `0.662→0.698`、`0.738→0.608`、`0.687→0.633` ms/次。本组 0% 没有提速，不能声称任何爆头率都更快。

## 更新规则后的实际代价

最终版本的两个 `deep` 分片再从空目录生成，默认目标是 170 级钢铁、无超宏、全身命中。毒芽 Prime **66.259 s**，三正评估从 36,190 变为 35,964；棱晶·安格斯壮 **97.327 s**，三正评估从 57,146 增至 74,618。两把的两正评估数保持 1,176 和 1,186。实际并行总耗时 **102.646 s**，比旧版的 83.418 s 长 23.1%。这是同一预算下按新规则走了不同的搜索分支，不能用上节的 3.5% 代替这个用户可见的结果。

棱晶·安格斯壮的三正推荐仍是 `D / CO / S`，致命负面仍是触发时间。但其负面词条的安全上限显示值从 98.2% 变为 98.0%；足以证明安全的既有配装命中从 4 次减为 2 次，完整标准搜索从 4 次增为 6 次。按三正和两正的全部候选数均摊，该武器进程 CPU 用时 **1.326→1.276 ms/评估**；慢在候选总数，并非每次回放更慢。另试过复用同一张卡的元素代理分数，最终分片逐字节相同，只减少 15 次评估、两武器墙钟差 0.034 s，未保留该改动。没有为得到较短的耗时而放宽 0.1 个百分点的阈值分辨率。今后要省这里的时间，应优先取得能通过实际复算的安全配装，不能用一个仍然偏低的代理分数直接宣判致命。

单张紫卡在线样本：同一棱晶·安格斯壮灵化形态、+179.9928% 暴击率、+108.0000% 暴击伤害。每轮用独立进程及该版本已校验的 `deep` 分片，清空完整请求缓存；不计进程启动和游戏数据载入。旧／新／新／旧四次分别为 **6.692 / 6.656 / 6.887 / 7.085 s**，旧版每次 11,716 次评估，新版 11,744 次，均无截断。在线请求没有复现这次离线阈值搜索的 19 秒增长；样本不足以承诺 P95 或所有武器的在线速度。

复用现有测试文件，对伤害、磁破、连续射速、组合枪、赋能、负面阈值和靶场做定向回归。Python/Rust shadow 组 171 项通过；正常缓存模式另外 13 项通过（shadow 按设计禁用该候选缓存）。修正了一条在冻结基线也失败的 Torid 测试：验证延时期间只多一次真实云场伤害事件，不再写死 `40 × 多重`；该文件的 22 项 Python 回放均通过。两把武器的正式对照报告位于 `shipping-deep/report.json`，基线在 `old-deep/report.json`。此版本的评分指纹为 `7f6b0632eef0a167`，旧规则分片不能作为新规则答案使用。

## 复现

分别在各版本源码下构建其 Rust 核心，换用未存在的 `$out`；默认灵化武器取末模式。完整工作量报告在 `$out/report.json`，其中 `searchWork` 同时记录正面结构、负面复核和截止次数。比较时先看枚举项是否相同，再看墙钟。

```powershell
python tools/build_native.py
$out = '.local/compare-two-deep/new'
$env:WF_ANALYSIS_STATICS_CACHE_PATH = "$out/isolated.json"
python tools/bake-analysis-statics.py --profile deep --workers 2 --status-tables off --shards-only --shard-dir $out --report "$out/report.json" --weapon /Lotus/Weapons/Tenno/Pistols/PrimeZakti/PrimeZaktiPistol --weapon /Lotus/Weapons/Corpus/Pistols/CrpHandRL/PrismaAngstrum
```

本轮报告与冻结源在 `.local/cpu-deep-followup-20261118/`；只发布源码与技术记录，不分发这两个样本分片。
