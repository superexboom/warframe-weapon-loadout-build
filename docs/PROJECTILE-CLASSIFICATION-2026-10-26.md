# 史特克分量修正、守望剩余偏差与次要照射静态审计

## 结果与适用边界

本轮纠正了上一报告“所有史特克胶团都按径向伤害处理”的过度概括。主胶团的附着跳伤、主爆炸、子胶团是不同事件：主爆炸可以是范围直击，触发资格不等于获得完整头部伤害倍率，也不等于吃 GunCO。模型保留用户指定的正常满层引爆，子胶团默认全部落在目标脚下，计算两次接触与末次爆炸；不引入官方初生满层回调 Bug。

守望继续使用原用户 JSON 的精确紫卡、等级、路线、赋能与敌人防御池。修复了灵化变形时间遗漏装填速度的问题，但短窗口 KPM 差异尚未消除。本轮没有用一个经验乘数把结果调到榜单，也没有宣称确定性期望回放已经等价于逐弹头随机回放。

## 守望：修复了什么，剩下什么

装填速度此前只影响换弹，没有影响灵化进出场。原配装的 Rapid Reinforcement 提供 +60% 装填速度，因此进场 `0.85 / 1.6 = 0.53125 s`，退场 `1 / 1.6 = 0.625 s`。Python 和 Rust 现在使用独立的 `transform_time_scale`，读取当前效果的装填速度桶；不通过灵化弹匣的伪换弹时长反推。普通击杀蓄能副开火仍保留自己的固定切换时长。

| 精确对照 | Portable 当前 KPM | WFSim KPM | 相对差异 |
|---|---:|---:|---:|
| 榜单设置，180 秒、瞄准、无外部增益 | 171.0934 | 166.6399 ± 0.0616 | +2.67% |
| 同上，30 秒 | 125.0000 | 109.3607 ± 0.2446 | +14.30% |
| 180 秒、原 Roar、未瞄准、普通 SP | 59.7849 | 62.0788 ± 0.0410 | -3.70% |
| 原文件，30 秒、未瞄准、精确匹配超宏 | 45.0959 | 42.2336 ± 0.1612 | +6.78% |
| 原文件仅打开瞄准 | 182.0000 | 178.0301 ± 0.0566 | +2.23% |

± 为 1,000 次均值标准误。180 秒射击数从 542 修正为 566，对照 565.67；30 秒 95 对 94.992。WFSim 的 transforms 只数进入灵化，本地数进出两方向，不能直接把两列当成频率差。

**先前约 -2% 的接近包含了误差抵消。** 修正偏慢的射击循环以后，确定性回放本身的乐观偏差暴露出来；不能保留错误动画时长来让总 KPM 更好看。

30 秒消融把问题进一步定位：

| 设置 | Portable | WFSim | 用途 |
|---|---:|---:|---|
| 完整配装 KPM | 125.0000 | 109.3607 | 总差异 |
| 去掉死首 KPM | 25.6247 | 25.1249 | 去掉最强击杀增伤反馈后明显接近 |
| 再去掉镀层分裂膛室、镀层瞄准 KPM | 4.4979 | 4.4708 | 击杀反馈消融 |
| 无击杀、无限生命、同一配装 DPS | 43,067,380.49 | 43,189,457.52 | 线性伤害约 -0.28% |
| 显式锁定四项增益满层，30 秒 KPM | 152.0000 | 134.6231 | 排除“只因叠层启动慢”的解释 |

显式锁定四项增益时，无击杀 DPS 为 660,663,103.37 对 655,347,227.44，约 +0.81%；有限生命 KPM 仍相差约 12.91%。对照必须使用 WFSim 的 `buffs:{stacks,locked}`：仅传旧 `assume_max` 并不等价于本地所有事件效果固定满层，早期该项试验不用于结论。

所以剩余误差不能只归给死首启动，也不是固定的面板倍率错了。本地把一枪伤害、触发数量和多个延迟分量按期望推进；其 16 个分支主要抽样弱点击杀归因，没有同时抽样每弹头多重、暴击、状态类型、各个球的独立伤害及击杀阈值。`击杀(期望伤害)`并不等于`期望(逐次击杀)`，完整配装跨越击杀阈值后又通过死首反馈放大这一差异。

128 条独立 WFSim 日志的首次击杀时间均值 5.2781 秒、范围 4.732–6.013，首次为头部击杀的比例约 91.4%；本地 16 条分支的首次击杀都发生在约 5.3313 秒，只展开之后的归因。死首 1/2/3 层的参考均值约 5.642/7.138/8.032 秒，本地时间线采样约 5.719/7.359/8.219 秒。这进一步否定了“本地单纯早叠死首，所以高 14%”的解释。抽样日志使用 `/api/log` 的 `run:[hi,lo]`，不是被该接口忽略的 seed。

补充隔离实验：只在本机诊断脚本中给直接伤害事件加入与现有方差匹配、均值为 1 的 Gamma 噪声（不调整均值、不拟合 WFSim），64 次锁定增益的 30 秒回放从 152 KPM 降到 **130.5 ± 0.42**，参考为 134.623。它进一步支持“期望值过早折叠导致击杀阈值偏差”，也表明粗粒度噪声并不等价于真实逐弹头采样。这个试验不进入生产评分，脚本和结果明确标记为近似诊断。

要继续消除这类偏差，应为高深度候选复评补充逐弹头随机/分层回放：离散多重和暴击、同弹头的状态快照、独立球事件、击杀清空与赋能反馈共同采样；用相同随机数比较候选，按置信区间和排名不确定度增加样本。快速搜索继续用当前 Rust 期望模型筛选，把较贵的回放集中在少量最终候选。仅增加现有弱点击杀分支数，无法覆盖缺失的随机变量。本轮完成原因隔离与时钟修复，**没有交付这个完整随机回放后端**；当前短窗口数值仍带上述模型误差。

## 史特克的分类与实际修复

依据当前静态声明，以及 WFSim 作者 2026-10-26 的 M127 原始实测记录：

| 分量 | 普通头部倍率/弱点伤害 | 死首头部增伤 | 条件弱点暴击/爆头暴击 | GunCO 伤害 | 弱点击杀 |
|---|---|---|---|---|---|
| 附着跳伤 | 不吃 | 不吃 | 不吃 | 不吃 | 不触发 |
| 主胶团爆炸 | 不吃 | 头部资格成立时吃 | 吃 | 不吃 | 可触发 |
| 脚下子胶团爆炸 | 不吃 | 不吃 | 不吃 | 不吃 | 不触发 |

“爆炸不吃爆头倍率”要明确是哪一项。普通头部 ×3、敏锐的弱点伤害被排除；死首 +30% 和符合条件的爆头暴击不能一并抹掉。M127 提供的基准：`(300+75)×3.2 = 1200`，头部死首为 `1560`；量化暴击倍率 `1.5003663` 后黄暴 `4681.14`、橙暴 `7802.29`。附着伤害仍是 `304×3.2=972.8`。新增回归复现这些数值。敏锐暴击加成的资格为报告明确确认，暴击频率没有单独测量。

同时修复：

- 胶团层数只乘原武器分量基伤，进化平坦基伤只加一次。两层灵化胶团是 `(300+2×200)×3.2=2240`，不是 `(300+200)×2×3.2`。
- 附着胶团在原目标死亡后保留剩余跳伤和爆炸；新目标的胶团按宿主 generation 分开，不与尸体上的旧胶团合并。基础/灵化胶团也不互相合并。
- 主爆炸的弱点事件进入死首等条件，跳伤和子胶团不借用该资格。胶团伤害事件补入 on-hit/Enervate 流程，保留其已有概率重置逻辑。
- 清除三个史特克模式与各伤害分量的 GunCO payload；保留镀层卡自己的触发率等其他属性。导入工具同时修正，避免下次导入恢复错误。

静态侧确认存在独立的 `ExplosionDirectHitDamageHitType` 字段：序列化位置 `Projectile+0x634`，构造默认 0，传给范围攻击参数；守望显式覆写为 DHT_RADIAL，而史特克未写同样的覆写。它证明“存在特殊直击分类通道”，但仅靠未写字段不能证明所有武器的弱点、CO、头部倍率行为。史特克本轮具体数值规则依赖上述测量，未把一项标志自动扩张成所有效果的总开关。附着胶团仍保存部署时的部分武器效果快照；完整的每次跳伤实时重算、动态蓄能及空间碰撞不在本轮完成范围。

自动配装验收：30 秒、9999 SP Thrax、灵化史特克、自动赋能、fast，约 141.62 秒；19,398 次 Rust 评估，0 Python 回退。最终选择 Secondary Fortifier，目标和手动复放均为 **19.1200755822 KPM**。死首已经合法参与候选，未为了模仿别人的配装强制选择它。

## 电/毒气与次要照射

**电、毒气头部种子的二次死首乘区已存在。** Python `expected_dot_damage` 与 Rust `tables` 对种子保留一次头部增伤，并在电/毒气落到头部时再乘一次；仅死首 +30% 时是 `1.3²=1.69`。不要求先有群体，原受击目标自己的头部电/毒气 tick 就能体现。邻居身体只继承头部种子，邻居自己的头部落点再加第二层。当前单目标模型没有邻居位置和弹跳落点，不能宣称已经模拟群体传播。

边界：这一核查针对乘法伤害种子。现有共享 accumulator 和电/毒气状态击杀的弱点归因还不是 M100 的完整空间实现，不能把种子测试描述成所有状态细节都已等价。

**次要照射没有一个通用“所有非即使命中 AoE ×2”的常量。** 当前 `RadialDamageOnMaxRadiationStackHit.lua` 解码 0 未知指令、0 无效跳转：

1. 条件对象排除 DHT_RADIAL、DHT_SCRIPT、DHT_DOT，并排除本赋能自身 intermediate；主条件要求目标 10 层辐射。
2. ApplyUpgrade 在目标上挂 OnDamaged 回调，等待一次调度后读取按目标索引的 `FrameHitCounter`，将 `GetStats` 的倍率乘以该计数，然后清零。
3. OnDamaged 也检查辐射层数和武器类型，但此回调本身没有同样的 HitType 过滤；它将攻击对象上的计数 accessor 累加到 FrameHitCounter。绑定 `0x1419c7bb0` 读取对象 `+0x244`。因此“触发一次照射”和“计入这一轮照射的伤害事件”不是同一套过滤。
4. DoRadialAttack 重新取 `WeaponStatsLib.GetProjectileAndDamageData` 返回的 `baseAmount`，复制暴击/伤害类型等数据，设置 `hitType=4`、`ignoreEntity=原受击目标`、`fallOff=0`。
5. 武器库再进入 native `0x141b9bf90`，通过投射物虚表 `+0x628` 的直击伤害构造路径；不是直接取刚才主胶团爆炸的 75/200 基伤。

所以两份回调贡献会得到 `1.8×2=3.6`，三份是 `1.8×3=5.4`。WFSim M59 已实测奏凯灵化 3.6 倍，但没有证明整个武器类都如此。史特克直击 AttackData.Amount 为 0，重新构造时若只有进化 +175，得到 175 基数与用户报告相符；以 175 为基数的一/二/三份照射分别是 315/630/945（尚未乘卡片、暴击、防御）。这是静态等价算术，不是本机实测伤害。

**尚未从静态数据证明“第一发一定一份、第二发一定三份”**：具体回调合并数量依赖目标、帧时序与投射物事件，不能仅凭攻击块数量决定。现有单目标解算把照射排除于自身伤害，和脚本 `ignoreEntity`一致；没有把群体照射加回原目标 KPM。

## 可继续验证的其他分类

新增可复跑工具 `tools/audit_projectile_classification.py`，从提取的 objects/parents 解析继承并保留每个字段的声明来源。本次得到 282 个候选投射物，其中 228 个有爆炸载荷、127 个有附着死亡载荷、19 个声明/继承 IgnoreHeadShotBonus、2 个显式声明爆炸直击 HitType。另提取 34 个赋能条件过滤对象。

值得继续对照的具体对象包括 Paris 家族灵化、Dread 灵化、Felarx 灵化、Lex/Lex Prime 灵化、Steflos 和 Alternox 的 wave projectile。它们与 Nataruk 一样存在 IgnoreHeadShotBonus 静态字段；部分已被其他径向/波动分支覆盖，**未按名称批量改成相同的完整战斗行为**。条件对象也显示 OnWeakPointHit 排除 radial/dot，而 OnWeakPointKillAnySource 只排除 radial。后续应分别检查伤害分类、命中部位、intermediate 来源、允许的触发器，不能再用单一 radial 布尔量推断所有效果。

## 锤子、Bot 与 GPU

锤类武器和锤类组合 Zaw 已取消自动必选剑风 Prime；包括显式选择 combo 的锤子。通过 HAMMERS_STANCE 与解析后的 HammerMeleeTree 两种来源识别。战刃投掷的已有例外保留，其他普通近战的原规则保留。候选池回归覆盖 Fragor Prime、Magistar、Rabvee/Shtung、Glaive Prime 和 Nikana Prime。

**Bot 尚未同步。** 后续移植必须带上 optimizer 的锤类识别、候选规则与回归；本轮涉及伤害字段、Rust能力标志、stackable状态机与combat-reference数据的修正也必须整组同步，不能只复制 optimizer 文件。

GPU 任务收束为批量烘焙：先把一批候选的静态解析与动态参数预打包，减少 Python resolver 回调，再评估同形态/同事件结构分批的 GPU 核心；保留 CPU 作为正确性基准。实时紫卡配装、单次手动模拟继续使用 CPU/Rust，暂不做 GPU 接入。本轮未启动烘焙、未构建 Portable EXE、未修改 Bot。
