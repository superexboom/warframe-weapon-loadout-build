# 紫卡分析：固定武器靶、去除评分与理论上限、爆炸部件导入

## 1. 固定武器靶（替代等级爬升校准）

- 靶：170 级钢铁之路凶魂百夫长，**去掉天生超宏护盾**（`noOverguard`），护甲 2700 不变；
  血量乘以 `healthScale`。超宏护盾会让磁力的易伤与按超宏池结算的破盾电击额外获利，
  导致配装几乎恒定出现磁力。
- `healthScale` 只由该武器**无紫卡基线**决定：两到四次窗口探测，使基线平均击杀时间
  为 `FIXED_TARGET_TTK_SECONDS = 3 s`；倍率与基线一起写入武器静态缓存。提交的紫卡
  永远不改变靶子，同武器的好卡、差卡、推荐都在同一个靶上比较。
- 删除压力校准、搜索后升靶、按等级迁移缓存。护甲在 170 级以上本就封顶，旧的等级
  爬升只是在放大血量与超宏占比（14% → 46%），每升一级要重搜两遍。
- 敌方选项 `noOverguard` / `healthScale` 只用于基准靶（`damage._enemy_enhancement_options`）。

## 2. 去除 0–100 评分与理论上限

旧评分 `(当前 − 基线)/(上限 − 基线)` 以「理论上限」搜索结果为分母，上限本身是近似
搜索，其误差会传到所有分数。现在：

- 不再计算上限配装、高数值反超修正、评分、评级、数值质量；
- 保留：相对无紫卡基线的实际增益 `actualGain`、逐词条贡献 `details`、推荐正/负面词条；
- 前端头条改为实际增益；配装页的「理论上限」切换改为「无紫卡基线」；
- `ANALYSIS_STATICS_CACHE_VERSION` 14 → 15。

## 3. 推荐词条：多流派基础配装

旧实现只在「无紫卡最优配装」上给每个词条打分，`_best_fixed` 只能从这套配装里删卡
腾位，不能换成别的卡；基础配装偏直伤时触发词条被系统性低估，反之亦然。现在另用
两张代表卡做完整搜索得到两套基础配装：

- 暴击卡：暴击率 + 暴击伤害 + 多重；
- 触发卡：触发率 + 该武器单词条最优的元素 + 多重；

每个词条、每个组合取三套基础配装中最好的结果；随武器静态缓存。推荐阶段取消了按
墙钟时间截断（原 8/15 s），排序不再随机器负载变化。

## 4. 爆炸 / 抛射体部件（`tools/import_projectile_components.py`）

101 个开火模式的导出数据带 `damage.components`，但没有审计过的回放剖面，爆炸伤害
完全没有计入（诊断 `projectile-component-damage-unapplied`）。导入器以 WFSim 的
`attack.radial` 为候选，要求三方一致才写入，否则记原因跳过：导出武器与直伤总量匹配
的开火模式；原生抛射体 `ExplosiveAttack`/`EmbedDeathAttack` 的 Amount 与参考总量一致
（类型显式一致，或 `DT_PHYSICAL` 取参考的冲穿切分）；半径、衰减、暴击、嵌入延迟取
原生（嵌入时间为区间时取期望中点）。已审计条目不覆盖。

本次导入 27 把，跳过 20 把（原因见 `docs/evidence/projectile-components-20261004/import.json`）。
无 MOD、170 级身体命中对照 WFSim：中位绝对误差 68.3% → 3.5%。仍偏差：Javlok +110%
（WFSim 中热 DoT 占主导，疑为爆炸触发的热 DoT 偏高）、Komorex −48%、Kulstar −50%、
Sepulcrum −42%。Kuva Seer / Kuva Ayanga / Tenet Spirex 的偏高来自对照请求未带赋灵
元素，补齐 60% 火焰后为 +13.5% / +13.9% / +4.2%。

`combat-reference.json` 原文件前 1546 行为 CRLF、其余为 LF，导入后统一为 LF；实际内容
变化为 +1116/−6 行（`git diff --ignore-cr-at-eol`）。

## 5. 其他发现

- Internal Bleeding / Hemorrhage / Magnetic Welt：运行时适配器早已建模，但目录准入不看
  适配器而被排除，已修（`app._manual_mod_rows`）。
- Euphona Prime：游戏导出两个模式均为半自动，WFSim 写作 `trigger: auto` 并据此拒绝
  半自动手枪炮击——WFSim 数据错误，本地正确。
- 只有条件词条、没有基础词条的卡（如 Repeater Clip「装填后射速」）被 `_mod_card`
  一律排除出优化器候选池；事件引擎支持其触发时可以纳入，影响所有武器候选池，待定。
- Hunter Munitions、狙击连击与开镜暴伤：已作为独立任务。

## 耗时

伯斯顿标准档（100% 爆头）：107.6 s → 70.3 s（加多流派基础配装前）。多流派基础配装
多两次完整搜索与三倍的推荐评估，均进武器静态缓存，同武器第二张卡起不再计算。

## 推荐词条验证

同一无紫卡基线配装（7 槽）+ 紫卡槽，分别装 WFSim 榜单紫卡词条与本地推荐的非融合词条
（同数量、满数值 1.0、无负面），两引擎在 170 级身体命中、无赋能下打分（两引擎排序在
8 把武器上全部一致）：

|武器|榜单 / 本地推荐（WFSim KPM）|
|---|---|
|Amprex|0.67 / 0.67|
|Pyrana Prime|1.95 / 1.99|
|Zakti Prime|2.27 / 2.45|
|Trumna Prime|0.57 / 2.68|
|Basmu|0.58 / 0.55|
|Kompressa Prime|1.85 / 1.68|
|Fulmin Prime|1.08 / 0.94|
|Verglas Prime|3.33 / 2.51|

改用各武器自身的分析靶（血量 ×0.014–0.034）重算本地 KPM：Verglas 51.3 / 50.1、
Kompressa 20.1 / 22.0、Fulmin 26.5 / 22.3。弱武器的固定靶非常脆，伤害溢出与弹药经济
权重上升，推荐偏向多重 / 弹匣 / 装填；Fulmin 在自身靶上仍落后 16%，是推荐流程的真实
不足（单词条粗排截断了需要协同的暴击组合）。验证用的是分层顺序而非推荐组合本身，
结论偏保守。
